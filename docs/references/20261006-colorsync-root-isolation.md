# ColorSync 生命周期隔离与本轮结论

日期：2026-10-06；macOS 26.5.1 / arm64。接续[当前源码两条件各 30 次对照](20261006-current-source-display-controls.md)。用户断开再接回 LG 后允许自主小批量测试；无法定位时整理已有优化、保留未解决问题。

## 结论

**确认的触发组合仍是：虚拟屏真实接入/移除 + 本机 LG 外屏连接条件。ColorSync 的重复显示信息请求累积没有解决。** 本轮进一步排除了“没有调用显示器对象析构”这一解释，验证提前释放并处理一秒事件无效；此前压力测试也未运行 OCU 显式布局配置事务。没有定位 XPC 发起 PID 或系统内部注册/重试路径，因此不能给 CalDigit、LG、ColorSync 或某一个 runtime 单独定责。

生产 helper/bridge 不做未经验证的改动。暂停继续热插拔压力，保留固定身份与显示器复用策略；它们是有效的记录增长控制和触发次数控制，不是此问题的根因修复。

## 本轮实测

每次 1920×1080 / 1×，固定已预热槽位 28；相同 Developer ID 签名，独立实验构建。只使用自己的 helper，不启动目标应用、捕获或输入。以下 CPU 是两项 ColorSync 服务累计 CPU 时间差之和，100% 为一核；每窗约 20 秒。变体按顺序运行，后两项是已有累积上的增量对照，不能当作各自独立的健康基线实验。

| 阶段 | ColorSync CPU | 显示信息请求/秒 |
| --- | ---: | ---: |
| LG 接回后的被动基线 | 1.78% | 0.198 |
| 提前释放变体开始前 | 1.67% | 0.197 |
| 提前释放变体 3 次后 | 10.28% | 1.381 |
| 原实现变体开始前 | 10.43% | 1.384 |
| 原实现变体 1 次后 | 13.19% | 1.781 |
| 显式色度坐标变体开始前 | 13.28% | 1.785 |
| 色度变体 1 次后，最终被动观察 | 16.31% | 2.176 |

共 5 次创建/退出，均确认 helper 退出及显示器移除，无清理错误、无在线 OCU 虚拟屏；物理屏拓扑在边界保持不变。没有重复 30 次测试。最终负载仍高于基线，未请求用户离开期间再做人工断开恢复，也未重启系统服务。

### 释放假设

三个实验变体都在自己的 helper 进程内给 `CGVirtualDisplay` 的 `dealloc` 加 begin/end 诊断，诊断里不查询 CG。原实现 1 次与色度变体 1 次均完成 begin/end。提前释放变体在创建时使用 autoreleasepool、显式置空最后强引用，然后跑一秒 RunLoop：3 次全部完成 begin/end，弱引用归零，但退出前 CG 仍报告显示器在线；进程退出后父探针确认移除。

这说明对象确实析构，且“一秒事件处理 + 提前释放”没有阻止累积。退出前 CG 状态仍在线不能单独证明服务残留，也不能推断更长等待必然无效；未将候选改动合入生产。

### 配置事务与色彩描述符

复查先前 Dev 30 次、当前内置屏 30 次、当前 LG 30 次的 90 个 ready 结果，全部 `configuration_applied=false`、`physical_origin_changes=0`。那些测试根本没有运行 OCU 的 `CGCompleteDisplayConfiguration` 事务，因此不能通过删除那段分支解释或修复已观察的累积。本轮 5 次同样没有运行该事务。

显式填写 [Chromium 测试 helper 的色度坐标](https://chromium.googlesource.com/chromium/src/+/HEAD/ui/display/mac/test/virtual_display_util_mac.mm)，作为缺省色彩描述符的候选对照。第一次后，146 份匹配 ICC 的总数没有变化、没有新文件，但其中一份现有 ICC 的 SHA-256 改变；守卫立即停止原定三次批次，保留自己的清理结果。没有手工删除、覆盖或恢复系统 ICC 文件。之后请求仍增加，不能宣称候选有效；这一批发生配置内容更新，亦不能用于严格的内容恒定对照。

## 调用者定位的实际边界

- 检测到约 30 个其他工作树/npm 安装的旧后台 App agent。旧 `agentInfo` 缺少 PID、活动会话和显示器资源数量，无法验证其无任务；未获得“全部可退出”的明确答复，因此保留。不能宣称已隔离全部显示消费者。
- ColorSync 日志携带用户凭据，但没有请求发起 PID；不能由凭据直接推断 WindowServer、OCU 或 useragent。
- 对一个旧 OCU agent 采样一秒，对 `colorsync.useragent` 与 ColorSync XPC agent 各采样五秒，只看到等待栈，未得到活动请求的发起栈；短时等待采样不构成排除其参与的证据。
- root ColorSync 服务的 `sample` 无权限；非交互管理员凭据也不可用。没有索要密码、关闭 SIP 或操作守护进程。因此本轮无法确认内部持续工作属于哪个注册/回调/重试对象。

下一层真正有区分度的验证是：健康基线下 LG 直连与原扩展坞链路的同构建对照、在明确无任务后关闭其他显示消费者、获取系统服务特权诊断并与最小复现一起提交。它们需要连接条件或诊断权限变化，本轮没有执行，不能把待测方案写成结论。

## 最早问题与已有优化

| 问题 | 已落实的处理 | 验证范围 |
| --- | --- | --- |
| 早期随机 serial / namespace 相关身份导致 ICC 与布局身份增长 | 跨 namespace 共用 32 个固定 serial 槽；创建锁保护分配，跳过在线/持有身份 | 预热槽反复复用时文件数量保持；首次使用新槽仍可能生成一份记录；不自动删历史 ICC |
| 会话开始/结束反复热插拔、Dock 重配置 | 默认保留空闲显示器并复用；支持显式 prewarm、精确 display ID、reuse/retain 参数 | 已有复用及 Dock 验证；首次接入、显式释放、App 退出和崩溃仍可能触发重配置 |
| 进程/虚拟屏是否实际释放不可确认 | 专用 helper 管道租约、EOF/停止、父进程检查系统移除，仅处理自身资源 | 本轮及前两条件压力测试正常退出与 CG 移除均通过；不等于 ColorSync 内部状态释放 |
| 外屏条件 ColorSync 持续请求 | 减少真实热插拔；明确兼容性限制并留下诊断工具 | 当前源码仍可触发，固定 serial 与正常对象析构并不足以修复 |

早期 `VirtualDisplayRunner --holder-only` 仍是随机 serial 演示，不适用于性能压力；实验 README 明确引导到固定身份、有界工具，未继续运行该路径。生产默认行为无需本轮再改。

## 留档与检查

新增仓库外变体构建器与最多三次的生命周期实验入口；检测 ICC 内容变化、拓扑变化或过高基线即停止，记录自身清理。脱敏数据见[本轮指标与构建指纹](../../experiments/DisplayPerformance/results-isolation-20261006.json)。原始日志、ICC 文件名、显示器身份和调用栈留在本地。10 项 Python 测试通过；三种 Swift/Objective-C 变体编译与严格签名验证通过。没有更改正式 App 产物，因此没有重启用户其他工作树的 App/runtime。
