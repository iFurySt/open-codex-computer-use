# 最小独立 demo 30 次创建/退出

2026-10-07，macOS 26.5.1 / arm64，内置屏 + LG。用户指出单次没有明显卡顿，要求与之前一样执行 30 次，而非由一次测试推断。

**同一个 71 行、无 OCU 链接的最小二进制，30 次后移除状态下的 ColorSync 合计 CPU 从约 19% 上升到约 99%，之后三段 30 秒静置仍约 99–100%。** 退出会降低在线峰值，但没有消除多次真实热插拔后的累积。是否达到可感知卡顿不能单凭 CPU 判断；用户在本轮 30 次与静置完成后明确反馈“有变卡的”；仍没有量化输入/帧延迟。

## 变量与清理

- 与前次[最小 demo](20261006-minimal-colorsync-reproducer.md)完全相同的 Developer ID 签名二进制，SHA-256 一致；没有重建成生产 helper。没有 OCU bridge/runtime 链接、NSApplication、AX、SCK、Metal、输入或布局事务。
- 固定预热身份槽 28，1920×1080 / 1× / 60Hz；每轮新独立进程依次 descriptor/init/apply，实际上线持有约四秒，正常停止/移除后等待两秒。十组三次，每组三次后 30 秒检查；开始两段 30 秒无热插拔基线，最后三段 30 秒静置。
- 30 次实际上线、进程 exit 0 与 CG 移除均确认；清理错误为零。所有边界 146 份 ICC 的数量和 SHA-256 完全一致；没有随机 serial、删除 ICC、重启服务或操作其他 runtime。检查点物理屏身份/坐标/主屏一致，没有在线虚拟屏。
- 起始已有约 19% / 3 请求每秒的异常状态，没有物理断开恢复成健康基线；本次是增量累积对照。其他工作树 runtime 仍保留，原外屏链路未与直连条件比较。不能据此确定内部系统缺陷、硬件责任或排除其他消费者参与。

## 定位含义

单轮增量现在获得 30 次曲线支持：这个最小私有显示器路径足以在当前环境反复触发持续负载。不需要把 GUI、捕获或目标窗口代码加入复现；但系统内部请求发起者仍未知，不能等同于“内部根因已修复/已定位”或“所有设备上都会这样”。固定身份控制记录增长、retain/reuse 控制实际热插拔次数，这两项仍只是对应问题的控制手段。

[脱敏曲线、构建指纹和清理结果](../../experiments/DisplayPerformance/results-minimal-thirty-20261007.json)。新增显式 1–30 次最小 demo controller，默认单轮工具的 25% CPU 守卫未移除；压力入口只在调用方明确要求下使用，仍对 ICC/拓扑变化、身份冲突及清理失败中止。17 项 Python 测试通过、二进制严格签名验证通过。正式 App 未改变，不重启其他工作树 runtime。

测试结束时仍有约 99% 合计 ColorSync CPU，没有自动恢复。此前人工断开/接回的恢复证据仍有效，但本轮没有执行该恢复，不套用旧测量作为本次已恢复结论。
