# Linux X11 explicit key hold

User request: submit a focused PR describing the game-input use case.

Add optional JS `holdMs` / native `hold_ms` to `pressKey` / `press_key`.
The Linux X11 bridge resolves a physical keycode and sends PRESS, bounded sleep,
then RELEASE in finally. Existing calls retain their delivery. Explicit holds
on other platforms fail clearly. SIGTERM during a hold attempts release and
modifier cleanup; SIGKILL is outside this guarantee.

Frame-polled games can miss a press shorter than a frame. An independent GTK
receiver measured about 4ms median with the old driver; 16ms polling saw 2/20.
The real REPL/MCP hold50 path measured 52.8–59.5ms and was sampled 10/10.
A separate mGBA 0.9.3 test restored the same FireRed title state for each case:
old Return missed once, old x worked, hold80 Return and x both reached the
initial controls screen. These are single application samples, not a stability
rate or evidence of completing a game. Actual timing measurements used a
local build of the hold implementation, before SIGTERM cleanup hardening.
