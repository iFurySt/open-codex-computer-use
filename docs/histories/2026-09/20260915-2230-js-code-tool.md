### 🛠 Changes Overview
**Scope:** `packages/OpenComputerUseKit`、`packages/OpenComputerUseJavaScriptShim`

**Key Actions:**
- **[runtime]**: 新增 `JavaScriptToolRuntime`——常驻 JavaScriptCore context，把 Computer Use action 暴露成同步的 `cua` API。
- **[shim]**: 新增 `OpenComputerUseJavaScriptShim`，提供设置/清除执行时限所需的 JavaScriptCore C 接口（Swift 侧没有对应 API）。
- **[tool]**: 新增 `js` 与 `js_reset` 两个 tool 定义及 dispatcher 分发。
- **[作用域]**: 每次 `js` 调用在自己的函数作用域里执行（`new Function`），所以 `let` / `const` 不会跨调用打架；需要跨调用存活的值挂到 `globalThis`，`js_reset` 清空。
- **[测试]**: 新增 `JavaScriptToolRuntimeTests`；tool 数量断言 9 → 11。

### 🧠 Design Intent (Why)
一个多步流程——取状态、找元素、点击、校验、失败重试——按 tool call 拆开的话，每一步都要往返一次，中间状态还得靠模型自己记。写成一段代码就只有一次往返，循环和重试是语言本身就有的东西。

API 做成同步的是刻意的：所有 action 都在进程内执行，没有真正的异步，硬套 promise 只会让模型写出更容易错的代码。

**明确的取舍**：这是在原有 9 个 tool 之外新增，不是替换。上游的 tool surface 是有意对齐官方 computer-use 的，`js` 只是叠在它们之上的一层组合入口；不用 `js` 的调用方完全不受影响。

fork 里 `js` 之上还有流式/预测执行引擎和 pi-bridge，那部分需要宿主侧的 feeder（MCP 不支持流式），不属于这个仓库，因此没有包含在内。
