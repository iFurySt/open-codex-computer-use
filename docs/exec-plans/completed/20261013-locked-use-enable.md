# Locked Use 单一启用入口

## 目标

用户只需 enable / status / disable 即可安装、授权并使用 Locked Use；验证模式不再是正常解锁的前提。在当前 PR 分支完成签名构建和实机闭环，验收后再合并。

## 范围

- 正常服务由管理员安装与签名检查决定可用性，保留双保护、许可、身份校验和重锁屏障。
- enable 完成安装后请求主 App 和 Guardian 权限；状态区分安装与权限就绪。
- 开发诊断入口不因正式启用而开放；旧验证记录只用于测试报告。
- 同步中英文使用指南及架构、安全、可靠性说明。
- 不发布版本、不自动合并 PR、不访问现有用户凭据。

## 验证方式

- Swift / Node / Python 回归，签名组件 ABI 与严格嵌套签名检查。
- 正式 App 的普通 enable 安装，权限检查，短时双屏遮罩、自动解锁、真实 AX 点击 / SCK、重锁与正常手动解锁。
- 任一失败先结束租约并确认保护释放，避免重复锁回用户会话。

## 实机迭代

- 普通 enable 安装成功，launchd 使用 --serve，主 App 和 Guardian 的实际权限检查均通过。
- 初次只读 observer 遇到冷签名校验 3.14 秒，超过 2 秒响应预算。只读响应预算调整为 6 秒，其他 RPC 与许可时限不变。
- 该延迟还触发旧服务将策略观察过期永久判为安装失效。改为过期停止当前工作但允许新观察恢复；真实策略失效仍禁用当前 epoch，新增两项回归通过。
- 本轮失败在解锁与显示遮罩前结束，双方保护释放，用户正常恢复桌面。正在正常卸载 / 重装修正版，再验证完整闭环。

- 普通 --serve 已通过一次完整的正常 MCP 解锁 / AX 点击 / 截图变化 / 5 秒保持 / 重锁和双保护释放闭环，用户正常解锁后看到 Counter: 1。
- 再测遇到 Agent 首次连接冷签名校验约 3 秒，旧 2 秒请求预算在遮罩启动前失败。改为首次握手 8 秒、动作与保护 2 秒；首次签名校验移到 4 个并发 worker 的独立队列，未认证 socket 与已认证连接总数最多 64，超时先 shutdown 并保留 fd 所有权至校验完成，避免复用竞态。新增独立控制队列回归通过。

- 异步首次校验后的实机闭环通过：锁屏后正常 MCP 自动解锁 / 捕获约 3.48 秒，AX 计数 0→1、截图变化、遮罩保持 5 秒、重锁、双方释放 ACK、正常手动解锁后同一窗口仍为 Counter: 1。用户确认可以并要求 rebase main 后推送。该闭环不代表完整系统凭据与故障矩阵全部验收。
