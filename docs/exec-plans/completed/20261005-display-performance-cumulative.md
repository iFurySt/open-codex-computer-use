# 累积启停与 ColorSync 恢复调查：有界采集完成

- 目标：按同一输入框体感比较基线、持有、移除及固定身份累积启停；隔离 ICC 新增与已有循环，提出可验证的恢复步骤。历史根因及恢复验收仍未完成。
- 边界：独立 demo，每批最多三次、共九次同身份启停。只清理自己持有的 helper，不重启主 App、系统服务，不删除 ICC 或修改色彩/物理布局偏好。用户批准系统重配置可能暂停主会话。
- 已完成：A/B/C/D 体感对照、三批九次已预热身份启停、批间物理屏恢复采集、最后五分钟被动观察、只读 ColorSync profile/耗时检查与自身客户端堆栈。
- 决策：用户离开后不追加热插拔，不要求体感答复；先保留故障现场。累计最后一批用户报告打字变卡，但本轮没有硬件事件到画面呈现的延迟测量。
- 无效对照：第二批后存在非 demo 显示器 223，首尾 CG 快照证明它实际在线；随后的时间对照虽首尾物理屏一致，日志仍处理该虚拟屏。两窗标为混杂，不作为单变量因果证明。
- 验证：四项指标/边界测试，独立 Objective-C 编译，146 份 OCU ICC 有效性检查，32 次在线屏 profile 查询，自身 helper 正常退出及当前物理屏确认。root daemon 堆栈权限不可用，没有提权。
- 结果：九次热插拔没有增加 ICC；最终仅物理屏的循环持续五分钟。最大嫌疑为显示重配置后的 WindowServer–ColorSync 重复同步；具体发起者和打字延迟的直接因果仍缺证据。
- 交付：扩展独立 demo、脱敏累计指标、调查报告与同任务 history。恢复方案为另一次显式授权的、保留配置的单次服务恢复前后对照；当前未执行。
